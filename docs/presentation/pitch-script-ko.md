# Top 4 발표 큐시트 · 5분 · 한국어

사용자 결정: 라이브 시연을 하지 않고 덱의 실제 화면 캡처로 흐름을 보여 준다. 문장은 평소 말투로 직접 말하고, 여기에는 슬라이드마다 꼭 짚을 것만 둔다. 덱은 [한국어판](spec-gap-replay-deck-ko.pdf). 목표 4분, 슬라이드를 넘기기만 하면 된다.

| 슬라이드 | 시간 | 꼭 짚을 것 |
| --- | --- | --- |
| 1 표지 | 15초 | 이름 · Spec Gap Replay · 기획 문서를 눌러 보며 따라가고, 문서가 답 없는 곳에서 멈추는 도구 |
| 2 문제 | 30초 | 정상 흐름은 금방 이해되는데 막히는 건 예외 · 예시 셋(시작한 사람이 승인해도 되나 / 이 버튼 누르면 뭐가 바뀌나 / 두 섹션이 다르면 어느 쪽) · 그래서 감으로 구현하거나 애매하게 질문함 |
| 3 동작 방식 | 35초 | **모델은 읽고, 판정은 코드** · Argon이 규칙 뽑고 원문 문장을 붙임 · 코드가 그 문장이 원문에 있는지 확인, 틀리면 다시 보냄(최대 3번) · 사람이 검토하고 엔진이 그대로 판정 |
| 4 문서 넣기 | 25초 | 실제 GitHub 공식 문서 3페이지 · Argon이 실제로 추출한 결과 · 구조 검사 113개 통과 · 규칙마다 원문 줄 번호, 사람이 넣고 뺄 수 있음 |
| 5 직접 눌러 보기 | 30초 | A는 이 배포를 시작한 검토자 · 자기 승인 금지 켜고 승인 → Blocked, 근거 62행, 상태 그대로 · 문서가 막은 거라 빈틈 아님 · 설정 끄면 같은 클릭이 Defined |
| 6 결정 못 하는 곳 | 30초 | 직접 만든 테스트 문서(앱에도 표시) · 6행은 승인, 9행은 반려 · 그래서 추측 안 하고 Needs decision으로 멈춤 |
| 7 질문으로 넘기기 | 20초 | Flash가 질문 초안, 사람이 확인하고 추가 · 경로 · 시작 상태 · 규칙 ID · 원문 두 줄이 같이 들어감 · Markdown으로 내보냄 |
| 8 챗봇과 다른 점 | 25초 | 챗봇은 빈틈을 그럴듯하게 채움 · 여기는 모르면 멈춤 · 결과마다 원문 줄 · 금지와 빈칸을 구분 |
| 9 한계 · 마무리 | 20초 | 실제 GitHub 경로에선 빈틈 못 찾음, 그래서 테스트 문서로 보여 줌 · 추출이 매번 조금씩 달라서 사람이 확인 · 코드 공개, Cloud Run에서 돌아가는 중 · 감사합니다 |

## 예상 질문 (답의 요점)

- 왜 Argon? → 2만 자를 한 번에 받아 규칙과 원문 인용으로 만들고, 검사에 걸리면 이어서 스스로 고침
- 추출이 틀리면? → 없는 문장·참조는 코드가 잡음, 뜻은 사람이 검토, Re-extract 있음
- 큰 PRD도? → 아직 검증 안 함, 지금은 요청·검토·승인 흐름, 경로는 사람이 눌러 봄
- 실제 문서에서 빈틈 찾았나? → 미리 정한 경로에선 못 찾음, 슬라이드에도 적음
- 실제로 돌아가나? → 지금 Cloud Run에 올라가 있고, 링크와 영상은 제출물에 있음
