# Top 4 발표 큐시트 · 5분 · 한국어

문장은 평소 말투로 직접 말한다. 여기에는 꼭 짚을 사실과 숫자, 클릭 순서만 둔다(사용자 지시: 대본 표현이 AI 같아 본인 말투로). 목표 4분 15초, 덱은 [한국어판](spec-gap-replay-deck-ko.pdf). 대비 영상 `spec-gap-replay-demo-v5.mp4`.

## 1 · 표지 (20초)

- 이름, Spec Gap Replay
- PRD를 눌러 보며 따라가는 도구, 문서가 답 없는 곳에서 멈춤

## 2 · 문제 (30초)

- 정상 흐름은 금방 이해됨, 막히는 건 예외
- 예시 셋: 시작한 사람이 승인해도 되나 / 이 버튼 누르면 뭐가 바뀌나 / 두 섹션이 다르면 어느 쪽
- 확인할 방법이 없어서 감으로 구현하거나 애매하게 질문함

## 3 · 동작 방식 (30초)

- 한 줄: **모델은 읽고, 판정은 코드**
- Argon이 규칙 뽑고 원문 문장을 붙임
- 코드가 그 문장이 원문에 있는지 확인, 틀리면 Argon에 다시 보냄(최대 3번)
- 사람이 규칙 검토 → 엔진이 그 규칙대로 결과

## 4 · 라이브 데모 (2분 10초)

1. GitHub 공식 문서 → **Use recorded run**
   - 말할 것: 실제 GitHub 문서 3페이지, 실제 추출 녹화본, 구조 검사 113개 통과
   - `line N` 하나 눌러 원문 줄 보여 주기 → **Start replay**
2. *Prevent self-reviews* 켜기 → **A**로 **Approve and deploy**
   - 말할 것: Blocked, 근거 62행, 상태 안 바뀜, 문서가 막은 거라 빈틈 아님
3. **Reset path** → 설정 끄기 → 다시 **Approve and deploy**
   - 말할 것: 같은 사람·같은 클릭, 설정만 바꿨더니 Defined
4. **Document** → **Test spec · conflicting approval rules** → **Use recorded run** → **Start replay**
   - 말할 것: 직접 만든 테스트 문서, 앱에도 표시돼 있음
   - Units `80` → Requester **Submit** → Reviewer **Approve**
   - 말할 것: Needs decision, 6행은 승인 / 9행은 반려, 그래서 멈춤
5. **Draft a question** → **Add to questions** → **Questions** → **Download .md**
   - 말할 것: Flash가 질문 초안, 경로·시작 상태·규칙 ID·원문 두 줄이 같이 들어감

시간 없으면 3번 건너뛰기.

## 7 · 챗봇이랑 뭐가 다른가 (30초)

- 챗봇은 빈틈을 그럴듯하게 채움
- 여기는 모르면 멈춤
- 결과마다 원문 줄, 금지와 빈칸을 구분

## 8 · 한계, 마무리 (15초)

- 미리 정한 실제 GitHub 경로에서는 빈틈 못 찾음 → 그래서 빈틈 장면은 테스트 문서
- 추출이 매번 조금씩 달라짐 → 그래서 사람이 규칙 확인
- 코드 공개, Cloud Run에서 돌아가는 중, 감사합니다

## 실패 대비

- 모델이 느리면: **Use recorded run**, "실제 실행 녹화본"이라고만 말하기
- 앱이 안 열리면: v5 영상 틀고 말로 설명
- 잘못 누르면: **Reset path** (검토와 질문은 남음)

## 예상 질문 (답의 요점)

- 왜 Argon? → 2만 자를 한 번에 받아 규칙+원문 인용으로 만들고, 검사에 걸리면 이어서 스스로 고침
- 추출이 틀리면? → 없는 문장·참조는 코드가 잡음, 뜻은 사람이 검토, Re-extract 있음
- 큰 PRD도? → 아직 검증 안 함, 지금은 요청·검토·승인 흐름, 경로는 사람이 눌러 봄
- 실제 문서에서 빈틈 찾았나? → 미리 정한 경로에선 못 찾음, 슬라이드에도 적음
