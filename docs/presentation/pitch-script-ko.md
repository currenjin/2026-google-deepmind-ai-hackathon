# Top 4 발표 대본 · 5분 · 한국어

발표는 한국어로 하고, 덱은 [한국어판](spec-gap-replay-deck-ko.pdf)을 띄운다. 제품 화면은 영어다. 발표 시간은 5분(사용자 전달)인데 Q&A 포함 여부를 몰라서 **4분 15초**를 목표로 잡고 45초를 남긴다. 아래 시간은 추정이고, 실제 리허설로 확인해야 한다. 영어 대본은 [script-en.md](pitch-script-en.md)에 있다.

무대에 오르기 전에 앱을 새 탭에서 열고 새로고침한다. GitHub Docs가 미리 선택돼 있다. 덱 PDF는 다른 창에 두고, 실패 대비로 `spec-gap-replay-demo-v5.mp4`를 준비한다.

## 0:00–0:20 · 1번 슬라이드 (표지)

안녕하세요, 정현진입니다. 오늘 보여 드릴 건 Spec Gap Replay입니다.
기획 문서를 개발자가 직접 눌러 보며 따라가고, 문서가 답하지 않는 곳에 닿으면 거기서 멈추는 도구예요.

## 0:20–0:50 · 2번 슬라이드 (문제)

PRD를 받아서 개발을 시작하면 정상 흐름은 금방 이해됩니다. 막히는 건 예외 상황이죠.
배포를 시작한 사람이 직접 승인해도 되는지, 이 상태에서 이 버튼을 누르면 뭐가 바뀌는지, 두 섹션이 다르게 말하면 어느 쪽을 따라야 하는지.
확인할 길이 없으니 결국 감으로 구현하거나, 애매한 질문을 보내게 됩니다.

## 0:50–1:20 · 3번 슬라이드 (동작 방식)

방식은 간단합니다. 모델은 읽고, 판정은 코드가 해요.
Gemini 4 Argon이 문서에서 상태와 역할, 행동, 규칙을 뽑고, 규칙마다 원문 문장을 그대로 붙여 옵니다.
그 문장이 원문에 정말 있는지, 참조가 맞는지는 코드가 확인하고요. 걸리면 오류 목록을 붙여 Argon에 다시 보내는데, 추출은 최대 세 번까지만 합니다.
사람이 규칙을 검토하고 나면 결정론적 엔진이 그 규칙대로 결과를 냅니다. 모델이 결과를 판정하지는 않아요.

## 1:20–3:30 · 4번 슬라이드 → 앱으로 전환 (라이브 데모)

전환: 브라우저로 넘어간다.

1. **GitHub 공식 문서 (실제 공개 문서, CC BY 4.0).** **Use recorded run**을 누른다.
   "GitHub 공식 문서 세 페이지를 Argon이 실제로 추출한 결과고, 녹화 시각도 같이 나옵니다. 구조 검사 113개를 모두 통과했어요."
   아무 `line N`이나 눌러 원문 줄을 보여 준다. **Start replay**를 누른다.
2. **Blocked.** *Prevent self-reviews*를 켠다. **A**(배포를 시작한 검토자)로 **Approve and deploy**를 누른다.
   "막혔습니다. Blocked by document, 근거는 62행이고 상태는 그대로예요. 문서가 금지한 행동이라 빈틈이 아닙니다."
3. **Reset.** 다음 장면 전에 **Reset path**를 눌러 같은 대기 상태에서 다시 시작한다.
   설정을 끄고 **Approve and deploy**를 다시 누른다.
   "같은 사람이 같은 버튼을 눌렀는데, 설정만 바꾸니 이번엔 Defined가 나옵니다."
4. **Needs decision.** **Document** → **Test spec · conflicting approval rules** → **Use recorded run** → **Start replay**.
   "이건 저희가 직접 만든 테스트 문서고, 앱에도 그렇게 표시돼 있습니다."
   Units에 `80`. Requester로 **Submit**, Reviewer로 **Approve**.
   "Needs decision이 나왔죠. 6행은 승인된다고 하고 9행은 반려된다고 해서, 엔진이 추측하지 않고 여기서 멈춥니다."
5. **질문 만들기.** **Draft a question** → Gemini 3.8 Flash가 초안을 쓴다 → **Add to questions** → **Questions** → **Download .md**.
   "질문에는 여기까지 온 경로와 시작 상태, 규칙 ID, 두 원문 문장이 그대로 들어갑니다."

시간이 부족하면 3번을 건너뛰고 4번으로 간다.

## 3:30–4:00 · 7번 슬라이드 (챗봇에 물어보면 안 되나요?)

그냥 챗봇에 물어보면 되지 않냐고 하실 수 있어요.
챗봇은 빈틈을 그럴듯한 답으로 채웁니다. 여기서는 모델이 구조만 뽑고, 판정은 검토한 규칙으로 코드가 내리니까 모르면 멈추죠.
그리고 결과마다 원문 줄이 붙고, 문서가 금지한 행동과 문서에 답이 없는 행동을 따로 보여 드립니다.

## 4:00–4:15 · 8번 슬라이드 (한계)와 마무리

한계도 두 가지 말씀드릴게요. 미리 정해 둔 실제 GitHub 경로에서는 빈틈을 찾지 못해서, 빈틈 장면은 테스트 문서로 보여 드렸습니다.
또 추출은 돌릴 때마다 조금씩 달라지는데, 그래서 replay 전에 사람이 규칙을 하나씩 확인하게 만들었어요.
코드는 모두 공개돼 있고 지금 Cloud Run에서 돌아가고 있습니다. 감사합니다.

## 실패 대비

- 모델이 느리거나 실패하면: 데모 문서마다 **Use recorded run**이 있다. "실제 실행을 녹화한 결과입니다"라고 말하고 이어 간다.
- 앱에 접속이 안 되면: `spec-gap-replay-demo-v5.mp4`를 처음부터 틀고 말로 설명한다.
- 버튼을 잘못 누르면: **Reset path**. 검토 결과와 저장한 질문은 그대로 남는다.

## 예상 질문

- **왜 Argon인가?** 2만 자 문서를 한 번에 받아 실행 가능한 모델을 원문 인용과 함께 만들고, 코드 검사에서 걸리면 이전 호출에 이어서 스스로 고칩니다.
- **추출이 틀리면?** 원문에 없는 문장이나 없는 참조는 코드가 잡아요. 뜻이 틀린 건 사람이 검토하고, Re-extract 한 번으로 다시 뽑을 수 있습니다.
- **큰 PRD에도 되나?** 아직 검증하지 않았습니다. 지금은 요청·검토·승인 흐름에 맞춰져 있고, 경로는 사람이 직접 눌러 봐야 해요.
- **실제 GitHub 문서에서 빈틈을 찾았나?** 미리 정한 경로에서는 못 찾았고, 슬라이드에도 그렇게 적었습니다.
