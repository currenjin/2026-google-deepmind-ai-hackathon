1표지15초
Spec Gap Replay · 결과 4종 배지

안녕하세요, 정현진입니다. 제가 만든 건 Spec Gap Replay예요.

기획 문서를 직접 눌러 보면서 따라가고, 문서에 답이 없는 지점이 나오면 거기서 멈추는 도구입니다.

2문제30초
질문 세 줄

개발하다 보면 PRD를 받죠. 정상 흐름은 금방 이해가 되는데, 막히는 건 예외 상황이에요.

배포를 시작한 사람이 자기가 승인해도 되는지, 이 상태에서 이 버튼을 누르면 뭐가 바뀌는지, 두 군데가 서로 다르게 쓰여 있으면 어느 쪽을 따라야 하는지.

이걸 확인할 방법이 없으니까 결국 감으로 만들거나, "이거 어떻게 해요?" 하고 애매하게 물어보게 됩니다.

3동작 방식35초
문서 → Argon → 코드 검사 / 사람 → 엔진 → Flash

원리는 한 줄이에요. 모델은 읽기만 하고, 판정은 코드가 합니다.

Gemini 4 Argon이 문서에서 규칙을 뽑으면서 원문 문장을 같이 붙여 와요. 그 문장이 원문에 진짜 있는지는 코드가 확인하고, 틀리면 Argon한테 다시 보내서 고치게 합니다. 최대 세 번까지요.

그다음 사람이 규칙을 한 번 보고, 엔진이 그 규칙대로만 결과를 냅니다.

4시작 화면15초
Document 화면 · GitHub Docs 샘플 선택

첫 화면은 이렇게 생겼어요. 문서를 붙여 넣거나 샘플을 고르면 됩니다.

오늘 보여 드릴 건 GitHub 공식 문서 세 페이지, 2만 자 정도 되는 실제 문서예요.

5추출과 검증25초
Verify 화면 · 113 of 113 checks passed

Argon이 실제로 추출한 결과예요. 위에 보시면 구조 검사 113개를 다 통과했고요.

오른쪽 규칙마다 원문 몇 번째 줄인지가 붙어 있어서, 사람이 보고 넣을지 뺄지 정할 수 있습니다.

6직접 눌러 보기30초
Replay 화면 · Blocked by document · 62행 인용

이제 버튼을 직접 눌러 봐요. A는 검토자인데, 이 배포를 시작한 사람이기도 합니다.

자기 승인 금지 설정을 켜고 승인을 누르면, 막혀요. 근거는 62행이고 상태는 그대로예요. 문서가 막은 거라서 빈틈이 아닙니다.

같은 설정을 끄고 똑같이 누르면, 이번엔 통과돼요.

7결정 못 하는 곳30초
Needs decision · 6행·9행 인용

이건 제가 일부러 만든 테스트 문서예요. 앱에도 테스트 문서라고 표시돼 있고요.

승인을 누르면 6행은 승인된다고 하고 9행은 반려된다고 해요. 그래서 추측하지 않고 여기서 멈춥니다. 이게 Needs decision이에요.

8질문으로 넘기기20초
Questions 화면 · Download .md

멈춘 지점은 바로 질문으로 만들 수 있어요. 초안은 Gemini 3.8 Flash가 쓰고, 사람이 확인해서 추가합니다.

질문에는 어떻게 여기까지 왔는지, 시작 상태, 규칙, 원문 두 줄이 같이 들어가서 마크다운으로 바로 보낼 수 있어요.

9챗봇에 물어보면 안 되나요?25초
모르면 멈춥니다 · 결과마다 원문 줄 · 막힌 곳과 빈 곳

그냥 챗봇한테 물어보면 되지 않냐고 하실 수 있는데요.

챗봇은 빈틈이 있으면 그럴듯하게 채워서 답해요. 이건 모르면 멈춥니다. 결과마다 원문 줄이 붙고, 문서가 막은 거랑 문서에 아예 없는 걸 따로 보여 줘요.

10한계 · 마무리20초
한계 세 줄 · GitHub 주소

솔직하게 한계도 말씀드릴게요. 실제 GitHub 문서에서는 빈틈을 못 찾아서, 빈틈 장면은 테스트 문서로 보여 드렸어요.

그리고 추출이 돌릴 때마다 조금씩 달라서, 사람이 규칙을 꼭 한 번 보게 만들었습니다.

코드는 다 공개돼 있고 지금 Cloud Run에서 돌아가고 있어요. 감사합니다.
